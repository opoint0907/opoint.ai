# 클로이 인스타그램 제작 (이미지)

인스타 콘텐츠는 **이미지**다. 기본 형식은 피드 캐러셀(4:5)이고, 영상(릴스)은 상은님이 따로 요청할 때만 만든다. 영상을 만들 때는 `opoint-yeon-episode` 스킬의 영상 규칙을 따른다.

## 힉스필드 계정: 반드시 '오포인트'

- 힉스필드 호출 전에 `list_workspaces`로 확인한다. 선택된 워크스페이스 id가 **`23be883d-aa3b-4171-8543-946428aff831`(오포인트)** 가 아니면 조회·업로드·생성 모두 하지 않고 멈춘 뒤 상은님께 알린다
- 보조 확인: `show_reference_elements`에 `char_o4_pingping`이 보여야 한다
- **`plan_type`이 `free`면 생성하지 않는다.** 무료 플랜 생성물에는 힉스필드 워터마크가 붙어 게시할 수 없다(IG01 v1에서 확인). 워터마크를 지우거나 잘라내지 않는다. 상은님께 알리고 유료 플랜 전환 후 진행
- 생성 전 `get_cost`로 비용을 확인하고 잔액과 함께 보고한다
- 엘리먼트·media_id는 계정마다 다르다. 다른 계정에서 읽은 ID를 섞어 쓰지 않는다
- 연결된 계정을 바꾸는 건 상은님이 claude.ai 커넥터 설정에서 힉스필드를 오포인트 계정으로 다시 연결해야 한다

## 0. 파일 구조: 흩어지지 않게

```
opoint-chloe-insta/
  SKILL.md           ← 이 파일 (프로세스)
  characters.md      ← 캐릭터 시트 SSOT. 캐릭터 묘사는 여기서만 복사
  episode-bank.md    ← 조합표 + 로테이션 로그 (지난 편 기록)
  voice.md           ← 멘트 규칙: 캡션, 카드 문구, 스토리, 댓글 답글, 멘션
```

- 에피소드 산출물은 `.claude/insta/IG{nn}_{제목}/`에 둔다
- **에피소드 폴더에 캐릭터 설정을 다시 적지 않는다.** 필요하면 characters.md를 링크한다
- 새 표정, 새 소품, 새 설정이 생기면 characters.md를 먼저 고치고 "마지막 갱신" 날짜를 바꾼다

## 1. 파이프라인

```
① 조합 뽑기       episode-bank.md의 5칸에서 고름 + 로테이션 로그로 3편 규칙 확인
② 로그라인       "[클로이의 면] + [관계] + [형식]" 한 줄
③ 슬라이드표     장 · 장면 · 클로이 표정/동작 · 핑핑 LED 표정 · 구도 · 카드 문구
④ 캐릭터 락 체크   아래 2절 표를 장마다 실제로 확인
⑤ 이미지 프롬프트  3절 구조, 영어, 레퍼런스 순서 고정
⑥ 검증 1회       적대적 검수 서브에이전트 (칭찬 금지, 결함만)
⑦ 비용 확인 → 상은님 승인 → 생성 (장당 1회, 2k)
⑧ 상은님 검수 → 수정이 필요한 장만 프롬프트 고쳐 재생성
⑨ 멘트           voice.md 규칙: 캡션, 카드 문구, 스토리, 댓글 답글
⑩ 기록           진행표(job_id) + 로테이션 로그 + characters.md 연속성 표
```

**①~⑥과 ⑨는 크레딧이 들지 않는다.** 한 번에 끝까지 만든다. ⑦ 생성은 상은님 승인 후에만 한다.

### 생성 규칙

- **캐러셀은 최대 3장** (2026-09-28 상은님 지시). 이야기는 커버 → 핵심 → 결말·떡밥 세 박자로 압축한다
- 핑핑 표정은 **공식 표정만** 쓴다. 새 표정을 만들지 않는다

- 모델 `nano_banana_pro`, `resolution: "2k"`, 캐러셀은 `aspect_ratio: "4:5"`
- 비용은 장당 2크레딧(2026-09-28 기준, 해상도 무관). 저해상도 테스트 단계는 없다
- **장당 한 번만 생성한다** (`count: 1`). 실패 판단은 상은님이 한다. 조용히 다시 뽑지 않는다
- `429 rate_limit_reached`는 제출 실패라 잡이 생기지 않고 과금도 없다. 그 장만 다시 제출한다(재생성 아님)
- `nano_banana_pro`로 요청해도 잡 기록에 `nano_banana_2`로 찍힐 수 있다. 진행표에 그대로 적는다
- 여러 장은 `generate_image_batch`로 한 번에 보내고 `jobs_wait` → `show_generation_by_ids`로 보여준다
- **이미지 안에 글자를 생성하지 않는다.** 카드 문구는 생성 후 편집에서 얹는다(모델이 한글을 틀리게 그림)

## 2. 캐릭터 락 체크리스트 (생성 전 장마다)

| 항목 | 확인할 것 |
|---|---|
| **폐쇄 캐스트** | "여자 정확히 1명 + 작은 떠 있는 로봇 정확히 1대, 그 외 없음"이 들어갔는가 |
| **클로이 머리** | 핑크·민트 웨이브 + 옆머리가 얼굴 양옆을 덮음 + 분홍 솜털 토끼 귀 |
| **클로이 의상** | 실내복(분홍 재킷)인가. suit 금지 |
| **클로이 레퍼런스** | `char_o4_chloe`만 (`_suit` 금지) |
| **핑핑 레퍼런스** | `char_o4_pingping` 참조가 있는가. **없으면 생성 중단** |
| **핑핑 표정** | characters.md 공식 표정 목록 안의 것인가. 마젠타 도트, 작게, 중앙 |
| **팀장** | 화면에 없음. 명령서 홀로그램만 |
| **글자** | 이미지 안에 읽히는 글자 없음. 홀로그램은 "흐릿한 글줄" |
| **연속성** | characters.md 5절 표와 맞는가 (외벽 상태, T-03 등) |
| **캐러셀 일관성** | 같은 편 안에서 조명, 시간대, 소품 위치가 장마다 이어지는가 |

## 3. 이미지 프롬프트 구조

```
REFERENCES      @Image 1 = Chloe, @Image 2 = Ping-Ping, @Image 3 = 장소, (@Image 4 = 소품)
                각 이미지에서 무엇만 가져오는지 한 줄씩. "take ONLY … Take nothing else."
SHOT            한 문장: 누가, 무엇을, 어떤 순간인지
CAST LOCK       exactly one young woman and exactly one small floating robot, no one else
CHLOE           characters.md 문장 그대로 + 이 장의 표정·동작
PING-PING       @Image 2 그대로 + 이 장의 LED 표정·위치·자세
COMPOSITION     4:5 세로, 렌즈(mm), 카메라 높이, 피사체 위치, 카드 문구 들어갈 빈 공간 위치
LIGHT & COLOR   같은 편 전체 공통 문장 (복사해서 씀)
STYLE           photoreal, 셀카 폰 사진 느낌 또는 시네마틱 스틸 중 하나
NO TEXT         No text, letters, numbers, logos or watermarks anywhere in the image.
```

- 레퍼런스 순서는 `medias` 배열 순서와 같게 한다
- 쓰지 않는 캐릭터나 소품은 **단어 자체를 쓰지 않는다** (부정문으로도 소환됨)
- 같은 편의 모든 장에 LIGHT & COLOR 문장을 똑같이 넣는다

## 4. 인스타 규격

| 형식 | 비율 | 픽셀 | 장수 | 비고 |
|---|---|---|---|---|
| 피드 캐러셀 (기본) | 4:5 | 1080×1350 | **최대 3장** | 1장째가 커버(훅). 마지막 장은 질문이나 떡밥 |
| 단일 이미지 | 4:5 | 1080×1350 | 1장 | 짧은 공지, 인사 |
| 스토리 | 9:16 | 1080×1920 | 3장 | 캐러셀 장을 재활용해 투표, 질문 스티커 |

- 피드 그리드(프로필)에서는 **3:4로 잘려 보인다.** 커버의 얼굴과 핵심은 가운데 3:4 안에 둔다
- 2k 생성본을 1080×1350으로 줄여 올린다

## 5. 조합표 · 로테이션

`episode-bank.md` 참고. 핵심 규칙:
1. **3편 규칙**: 연속 3편 안에서 같은 형식이나 같은 결말을 반복하지 않는다
2. **떡밥 한 줄**: 매 편 다음 편으로 이어질 장치 하나 (T-03, 외벽, 팀장 명령서 등)
3. **4주 비율**: 코미디 50%, 전문가·정보 25%, 감성·미스터리 25%
