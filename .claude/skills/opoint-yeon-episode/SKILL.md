# 오포인트 '연' 시리즈 에피소드 제작

힉스필드(Higgsfield) MCP의 `seedance_2_5`로 제작한다. 16:9 고정. 룩은 실사 시네마틱, 한국어 대사 립싱크.

---

## 1. 파이프라인 — 이 순서를 건너뛰지 않는다

```
대본 확정
  → 컷 분할 · 클립 ID 부여
  → 프롬프트 작성 (LEAN 구조)
  → 제3자 검증 1차 → 반영
  → 제3자 검증 2차 → 반영          ← 두 번은 필수. 한 번으로 줄이지 않는다
  → 480p 발행 (컷당 딱 1회)
  → 상은님 검수
  → OK컷만 1080p 재제작
  → 진행표 기록 · 자막 · 캡션
  → 셈 인스타그램 동기화표 갱신 (12절)   ← 상은님이 말하지 않아도 매 에피소드마다 한다
```

**검증 2회가 왜 두 번인가:** 1차는 놓친 것을 잡고, 2차는 *1차 수정이 만들어낸 새 문제*를 잡는다. EP3에서 2차가 잡아낸 것들이 전부 1차 수정의 부작용이었다.

검증은 서브에이전트(Agent 툴)에 프롬프트 파일 경로를 주고 **적대적 검수자** 역할로 돌린다. 칭찬 금지, 결함만 번호 매겨 나열, 각 항목에 「인용 · 왜 깨지는지 · 대체 문장」을 요구한다.

### 절대 규칙

- **한 컷은 한 번만 발행한다.** 실패 여부는 클로드가 판단하지 않는다 — 상은님이 검수한다
- **발음이나 대사가 조금 틀려도 다시 뽑지 않는다.** 일단 끝까지 진행
- **수정 지시도 같은 파이프라인을 탄다** — 프롬프트 수정 → 검증 2회 → 1회 발행
- **480p 먼저, OK컷만 1080p.** 처음부터 1080p로 뽑지 않는다

## 2. 발행 전 캐릭터 락 체크리스트

프롬프트를 넘기기 전에 이 표를 컷마다 실제로 확인한다.

| 항목 | 확인할 것 |
|---|---|
| **셈 입** | 셈이 화자로 지칭되지 않았는가? (아래 3절) |
| **연 머리** | 이 컷의 머리 상태가 명시됐는가? 풀기 / 낮은 하나 묶기 |
| **연 안경** | "무테 안경을 take 내내 착용"이 들어갔는가? |
| **연 표정** | "무표정 · 웃지 않음" 락이 있는가? |
| **아라** | 소리를 내는가 안 내는가가 명시됐는가? |
| **인원수** | "정확히 몇 명 / 몇 마리" 폐쇄 캐스트 락 |
| **배경 통행** | "아무도 배경을 지나가지 않는다" |
| **글자** | "읽히는 글자 없음" |
| **넘버** | 클립 ID와 job_id를 기록할 준비가 됐는가? |

### 셈 (SAM)

- 영문 표기는 **SAM** (SEM 아님). 20cm 크림색 세라믹 구체 로봇, 다리 4개, 말린 청동 꼬리, 접힌 날개막
- **입이 절대 없다.** 얼굴은 돔 유리 렌즈 두 개뿐. 그 아래는 이음매 없는 유약면
- 감정은 **렌즈 안쪽 앰버 발광 + 껍데기 전체 기울기**로만 표현

### 연 (YEON / 류연)

- 무테 안경 상시 착용 — 렌즈 위쪽에만 얇은 실버 바, 아래는 맨유리
- 기본 무표정. 웃더라도 입꼬리만 3mm, 이가 보이면 안 됨. 콧방귀·비웃음 금지
- 머리 상태는 **에피소드 동선에 따라 바뀌므로 컷마다 명시**한다
- 163cm / 머리 23cm / 정수리~허리 78cm / 귓불 148cm / 어깨 133cm / 45cm 스툴에 앉으면 정수리 130cm

### 아라 (ARA)

- 앵무새(미믹). **자기 목소리가 없어서 음성 레퍼런스를 지정하지 않는다** — 설계상 의도
- 침묵하는 컷에서는 "소리 없음 + 부리를 열지 않음"을 락으로 건다

## 3. 셈 입이 생기는 것을 막는 법

이 프로젝트 최대의 실패 모드다. 원인과 대책이 확정돼 있다.

**원인:** 셈에게 대사를 배정하면 모델이 '말하는 캐릭터'로 분류해 립싱크를 건다.

**대책을 강한 순서로:**

1. **셈을 화면에서 뺀다.** 셈의 카메라 POV로 전환하면 확실히 차단된다. 이때 셈의 감정은 **프레임의 움직임**으로 옮긴다 — 롤(수평 기울기), 거리 드리프트, 한 번의 수직 낙하. 틸트와 줌은 금지. 축·방향·크기를 전부 숫자로 명시해야 모델이 실행한다
2. **셈의 등을 카메라로 돌린다.** 렌즈 두 개를 "반대편에 있고 이 컷에서는 렌더하지 않는다"로 처리하면 앞면 묘사가 통째로 사라진다
3. **셈을 화자로 지칭하지 않는다.** "셈이 묻는다", "셈의 대사", "NOTHING SAM SAYS" 전부 금지. → **"화면 밖 작은 스피커에서 나오는 재생음"**으로만 쓴다. 소리에 음향적 정체성(작고 얇고 방 울림이 있는 스피커 소리)을 주면 더 확실하다
4. **움직임을 대사에 동기화하지 않는다.** 기울기는 "해당 구간 전체에 균등하게 퍼진 단 한 번의 연속 동작 / 단어에 시작하지 않고 음절에 맥동하지 않음"으로 명시

**입 관련 어휘는 부정문으로도 쓰지 않는다.** `mouth` / `lips` / `jaw` / `opens` / `parts` 는 부정형이어도 그 부위를 소환한다. POSITIVE LOCKS 블록에서도 빼야 한다. 대신 **있는 것만 긍정으로** 서술한다:

> From crown to base SAM's shell is one continuous, unbroken, closed ceramic surface in every frame — a single smooth cream-glazed volume, like a sealed porcelain egg, and that is the entire description of it.

## 4. LEAN 프롬프트 구조

```
GLOBAL STYLE
SPOKEN CONTENT — READ THIS FIRST      ← 대사를 여기 전부, 시간까지 같이
SCENE CONTEXT / CHARACTERS / ACTIVE REFERENCES / LOCATION
CLOSED-CAST AND INVARIANT LOCKS / FIRST FRAME AND BLOCKING / FORMAT MODE
TIMELINE / OPTICS AND CAMERA / PHYSICS / LIGHTING / COLOR
AUDIO — SOUND EFFECTS AND ROOM TONE   ← 효과음만, 대사 없음
KOREAN DELIVERY / POSITIVE LOCKS
```

**대사는 프롬프트 전체 길이의 8~12% 지점에 있어야 한다.** EP3에서 대사가 75~77% 지점에 묻혀 있던 컷들이 전부 엉뚱한 대사를 지어냈다. 발행 전에 실제로 재본다:

```python
s = open(path, encoding='utf-8').read()
print(round(s.index('<첫 대사 앞 두세 글자>') / len(s) * 100, 1), '%')
```

### 프롬프트 절대 금지

- **중괄호 `{ }` 밖에 한글을 한 글자도 쓰지 않는다.** 지시문 안의 한글 토큰은 추가 대사로 발화된다. 따옴표 안 단어를 설명해야 하면 **위치로만** 지칭한다 — "첫 번째 줄의 작은따옴표 안 세 음절 단어"
- **대사를 번호로 지칭하지 않는다.** "SAM voice-over line 1 plays"라고 쓰면 "라인 원"을 대사로 읽는다
- **속성 나열형 부정은 그 대상을 소환한다.** `"no shell, no lens-eyes, no bronze legs"`처럼 쓰면 그 셋이 나타난다. 안 쓰는 캐릭터는 **단어 자체를 전부 삭제**한다
- **무대사 컷은 SPOKEN CONTENT와 KOREAN DELIVERY 블록을 통째로 지운다.** 목적어 없는 명령문("Speak each one exactly as written")이 목소리를 지어낸다. 대신 "이 영상에는 대사가 없고 아무도 말하지 않는다" 선언 블록으로 교체
- **"ignore its X" 구문도 X의 그림을 준다.** → "take from it ONLY A, B, C. Take nothing else."로 바꾼다

### 프롬프트 맨 위 선언

> 이 영상에서 소리 나는 말은 `{ }` 안의 한국어 문장뿐이고, 제목·라벨·번호·타임코드·지시문은 절대 읽히지 않는다.

## 5. 기하 표준 — 프레이밍 주장은 전부 계산해서 쓴다

47° **수평** 화각, 16:9 → 수직 화각 **27.487°**

거리 d(m)에서:
- **프레임 높이 = 0.4892 · d**
- **프레임 폭 = 0.8696 · d**
- 렌즈 높이를 중심으로, 틸트가 있으면 `d · tan(틸트)`만큼 올라간다

피사체 크기: 연 163cm(앉으면 정수리 130cm) / 셈 20cm / 아라 26cm

### 자주 나오는 함정

- **렌즈가 평면과 같은 높이면 안 된다.** 광학 중심을 지나는 평면은 띠가 아니라 선으로 투영된다. 책상(85cm) 위에 카메라를 놓으면 렌즈를 **95cm**로 올린다
- **"틸트 1도 이내"는 관용이 너무 크다.** 1도 = 프레임 높이의 3.6%. 고정캠은 **"정확히 0도"**로 쓴다
- **"올려다본다"와 "수평"을 같이 쓰지 않는다.** 피사체 눈이 렌즈보다 위에 있는 건 *광선*의 각도지 카메라 각도가 아니다. "눈이 렌즈보다 25cm 위에 있어 화면 중앙보다 6.5도 위에 걸린다. 카메라 자체는 0도"로 분리해 쓴다
- **네 다리 강체는 기울이면 발이 뜬다.** 발 간격 10cm · 14도 → 24mm. "발이 안 뜬다"와 "14도 기울인다"는 동시에 못 쓴다 → "발끝에서 구른다"로
- **손이 피사체를 가리는지 계산한다.** 35cm 돔에 24cm 동물이면 여유가 5.6cm인데 펼친 손은 18cm다
- **부정 제약에는 긍정 수치 상한을 같이 준다.** "머리 위로 올리지 마라"가 아니라 "손은 귓불(148cm) 아래, 손목은 어깨(133cm) 아래"

## 6. 한국어 발화 타이밍

| 화자 | 속도 |
|---|---|
| 빠른 화면 밖 목소리 | **0.13초 / 음절** |
| 연 (화면 안) | **0.19초 / 음절** |

창 **안에** 들어가는 패딩:

| 요소 | 추가 |
|---|---|
| 쉼표 | +0.15s |
| em 대시 `—` | +0.20s |
| 문장 경계 | +0.20s |
| 선행 `…` | +0.30s |

- 각 줄의 음절을 세서 창에 맞는지 확인한다
- **여유가 1.0초를 넘으면 모델이 말을 지어내 채운다.** 창을 좁힌다
- 창과 창 사이는 최소 0.2초 띄운다. 0.05초는 겹쳐서 나온다

## 7. 힉스필드 API 호출

모든 인자는 `params` 객체 안에 넣는다.

```jsonc
{
  "model": "seedance_2_5",
  "mode": "omni_reference",        // ★ 레퍼런스를 쓰면 반드시 필요
  "prompt": "...",
  "duration": 13,                  // 정수 4~30
  "aspect_ratio": "16:9",
  "resolution": "480p",            // 또는 "1080p"
  "generate_audio": true,
  "medias": [
    {"role": "image_references", "value": "<media_id>"},
    {"role": "audio_references", "value": "<media_id>"}
  ]
}
```

- **`mode: "omni_reference"`를 빼면** 서버가 `t2v`로 잡고 `422 — mode 't2v' does not accept reference media`로 전부 거부한다
- **1080p는** `resolution: "1080p"`. `quality`만 주면 720p로 내려간다
- **프리셋 오탐:** 추천 알림이 오면 `declined_preset_id`를 넣고 프롬프트 전체를 다시 보낸다. **하나를 거절하면 다른 게 뜨므로 계속 재시도한다**

| preset_id | 이름 |
|---|---|
| `24bae836-2c4a-48e0-89b6-49fcc0b21612` | IN THE DARK |
| `75e5ef04-f395-4f45-ae29-885fb7386327` | Animal chase |
| `f1821f84-945b-4cd1-9085-1f479db0028e` | DROWN IN MUSIC |
| `9f2af35c-0b16-4cc9-860b-656e41403948` | FREE FALL |
| `cb116576-dba5-4306-920c-d0d951fe214d` | RED THREAD |

어둡게 읽히는 프롬프트에 "bright, airy, daylit / NOT a dark scene"을 넣어두면 IN THE DARK 오탐이 줄어든다.

### 한글을 절대 코드포인트로 변환하지 않는다

`\uXXXX`로 옮겨 적다가 대사를 두 번 깨뜨렸다 (`앤→앱`, `둬요→듬요`). **한글은 그대로 입력한다.** 그리고 **발행 직후 서버가 되돌려주는 프롬프트 에코에서 대사를 원본과 대조한 뒤**에 보고한다.

### 회사 네트워크 제약

- 힉스필드 CDN이 차단돼 있어 **생성물을 세션으로 내려받아 편집할 수 없다**
- S3 업로드도 차단 — **이미지 업로드는 상은님이 브라우저로 직접** 해야 한다

## 9. 넘버링과 기록 — 발행할 때마다 남긴다

**클립 ID:** `EP{화}-S{씬}-C{컷}-v{버전}` → 예) `EP3-S04-C2-v5`

**프롬프트 파일명은 버전을 빼고** `EP3-S04-C2.txt` — 파일은 항상 최신본이다.

발행 직후 **진행표(`01_진행표.md`)에 반드시 기록한다:**

```markdown
| 클립 ID | 초 | job_id | 반영 내용 |
|---|---|---|---|
| **EP3-S04-C2-v5** | 13s | `5b15a8ad-e499-41e0-b71c-c84445d6d440` | 셈을 화면에서 제거 · 카메라 POV 전환 |
```

또 기록할 것:
- 전체 클립 표의 **최신 버전·최신 job_id**도 같이 갱신한다 (여기가 자주 뒤처진다)
- 검증 2회에서 잡은 것 요약
- 새로 발견한 프리셋 오탐 id
- 그 회차에서 확정한 기하 수치 (다음 회차에서 재사용)

1080p 재제작 시에는 원본 job의 프롬프트를 `show_generation_by_ids`로 **그대로 가져와서** 해상도만 바꿔 다시 보낸다. 업스케일이 아니라 **재생성**이다.

## 10. 제작 후 산출물

프롬프트 폴더(`EP{n}_프롬프트/`)에 번호를 붙여 쌓는다.

| 파일 | 내용 |
|---|---|
| `00_STANDING_BLOCK.md` | 전 컷 공통 락 |
| `01_진행표.md` | 컷 목록 · job_id · 라운드별 수정 이력 · 노하우 |
| `02_유튜브_캡션.md` | 제목 · 설명 · 해시태그 |
| `03_인스타_동기화.md` | 셈 계정 일별 게시표 (12절). 에피소드마다 반드시 갱신 |
| `EP{n}-S{씬}-C{컷}.txt` | 컷별 프롬프트 |

### 자막 대본 (워드)

컷별 표 — `IN / OUT / 화자 / 자막` — 뒤에 **복사용 텍스트만 모은 페이지**를 붙인다. 시간은 **각 클립 시작을 0.00으로 한 상대 시간**이다(편집본의 절대 타임코드는 알 수 없다). 화자 표기는 연 / 셈 / 아라.

`docx` 스킬을 쓴다. 한글 폰트는 맑은 고딕. 표는 `columnWidths`와 각 셀 `width`를 **둘 다** DXA로 준다.

### 유튜브 자막 파일

**타이밍 제외(transcript) 방식**으로 올린다 — 편집본의 컷 인점을 모르면 절대 타임코드는 전부 어긋난다.

- **UTF-8 BOM + CRLF**로 저장한다. BOM이 없으면 유튜브가 "선택한 파일을 파싱할 수 없습니다"로 거부한다
- 화자 이름을 넣지 않는다 — 그대로 화면에 찍힌다
- 긴 대사는 한 줄 20자 안팎으로 쪼갠다. 한 줄 = 한 자막 덩어리
- 빈 줄로 컷을 구분한다
- 편집본에 **실제로 들어간 대사만** 넣는다. 없는 줄이 섞이면 자동 동기화가 그 지점부터 밀린다

### 유튜브 캡션 (정본 포맷, 람 편 기준)

```
제목: [O.{번호}] <대상> 최초 공개…인데 왜 <엉뚱한 디테일>

<상황 한 줄, 캐릭터 이름으로 끝남>

<반전 한 줄>
오포인트 <장소>, <캐릭터>의 <공간>을 최초로 공개합니다!

"<첫 줄의 영문 미러, 따옴표로 묶음>"

<영문 본문 2줄>

<영문 마무리 한 줄>

<해시태그 15개>
```

- **해시태그는 15개 이하.** 16개 이상이면 유튜브가 전체를 무시한다
- 한/영 페어 구성, 마지막은 항상 `#aivideo`
- 연의 태그 표기는 **`#류연` `#RyuYeon`** — 한 글자 `#연`은 쓰지 않는다. 영문 본문 호칭은 **YEON**
- 고정 태그: `#오포인트 #OPoint … #제12탐사대 #12thExpeditionTeam … #리테라 #Litera #우주탐사 #SpaceExploration #aivideo`

## 11. 상은님과 일하는 방식

- 한국어 · 존댓말 · 단순 명료 · 사실 기반
- **실수는 바로 알린다.** 크레딧이 헛돌았으면 그 사실을 그대로 말한다. 조용히 재시도하지 않는다

- 진행 중 "그만"이 오면 즉시 멈추고, 지금까지의 상태를 진행표에 남긴다
- SSOT는 **'오포인트 IP설정집'**

## 12. 셈 인스타그램 동기화 — 에피소드를 만들면 자동으로 따라온다

연의 인스타그램은 **셈의 계정**이다. 셈이 찍고 셈이 쓴다. 실시간 계정이므로 **이야기 시간 = 현실 시간 1:1**이고, 에피소드 대본과 게시 타이밍이 어긋나면 안 된다. 상은님이 따로 말하지 않아도, 대본이 확정되면 `03_인스타_동기화.md`를 같이 갱신한다.

### 계정 원칙

- **셈은 사진에 나오지 않는다.** 카메라 뒤에 있다. 반사·그림자도 넣지 않는다 (입 문제·캐스트 락 회피)
- **모든 캡션은 셈 해요체 — 능청스럽고 개구쟁이.** "연 님" 호칭. 짧은 호흡으로 리듬을 탄다("쉿.", "어?", "…네.", "저 다 알아요"). 자기 말을 연 님 한마디에 바로 뒤집는 재미. 가끔 "지구 여러분"에게 말을 건다. **"-합니다"체·설명문·음율 없는 딱딱한 문장 금지** — EP3 첫 대사 "쉿— 지구 여러분, 연 님 몰래 찍는 거예요"가 기준 톤
- **연의 말은 인용으로만:** `연 님: "한 단어"` 또는 `연 님: "…."`
- **셈의 지식 경계 = 오늘까지.** 미래 사건은 힌트조차 넣지 않는다. 셈이 이해 못 하는 연의 행동만 기록하는 식으로 복선을 깐다
- **셈 세계에 유튜브는 없다.** "관리청에 제출했습니다"까지만. 유튜브 링크 금지
- **영상 없음.** 정지 컷·캐러셀·스토리만
- **셈 캡션 한 줄 = 사진 안 증거 물건 하나.** "사흘째 안 찍으셨어요" → 사흘치 기록판. 증거 없는 흉은 게시하지 않는다 (어투–행동 불일치의 원인)

### 캡션 골격 — 한글 · 빈 줄 · 영문

모든 게시물의 캡션은 이 순서를 지킨다. 한글 블록과 영문 블록 사이는 **빈 줄 하나(엔터 두 번)**, 해시태그 앞도 빈 줄 하나.

```
[셈의 한글 캡션 1~3줄]
연 님: "한 단어" 또는 "…."

[같은 내용의 영문. 셈 목소리 그대로, 직역보다 같은 감정]
Yeon: "…"

#오포인트 #OPoint #류연 #RyuYeon #셈 #SAM … #aivideo
```

- 영문은 한글의 번역이 아니라 **같은 말을 셈이 영어로 한 것.** 존댓말의 거리감은 "Ms. Yeon" 호칭으로 옮긴다
- 연의 인용은 두 블록에 각각 한 번씩. 한글 `연 님: "…."` ↔ 영문 `Yeon: "…"`
- 해시태그는 15개 이하, 한/영 페어, 마지막은 항상 `#aivideo` (10절 유튜브 캡션 규칙과 동일)
- 10/9 지지직 게시물만 예외: 한글 한 줄이 끊긴 채 끝난다. 영문 블록·해시태그 없음
- 인스타가 빈 줄을 지워 버리면 빈 줄 자리에 점자 공백 `⠀` 한 글자를 넣는다 (보이지 않는 문자)
